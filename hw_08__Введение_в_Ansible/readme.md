Команда 

    ansible-playbook -i inventory/test.yml site.yml 
    запускает выполнение Ansible‑плейбука для автоматизации настроек или развёртывания на целевых серверах.

Что делает каждая часть команды:

    ansible-playbook — утилита для запуска плейбуков в Ansible. Плейбук (в данном случае site.yml) — это YAML‑файл, где 
        описаны задачи (например, установка пакетов, копирование файлов, перезапуск служб), которые нужно выполнить 
        на удалённых хостах.
    -i inventory/test.yml — опция -i задаёт путь к инвентарю (списку хостов). Здесь Ansible берёт список целевых машин
        и их группировку из файла inventory/test.yml. Инвентарь может быть в формате INI или YAML и определяет, на 
        каких серверах будут выполняться задачи плейбука.
    site.yml — имя самого плейбука, который будет исполнен. В нём обычно прописаны секции hosts (на каких группах 
        хостов работать), переменные, роли и список задач.

Как это работает пошагово

    Ansible читает инвентарь inventory/test.yml, чтобы понять, какие хосты задействовать.
    Загружает плейбук site.yml и проверяет его синтаксис.
    Сопоставляет хосты из инвентаря с секциями hosts в плейбуке (если в плейбуке явно указана группа или паттерн 
        хостов).
    Устанавливает SSH‑соединение с каждым подходящим хостом (или использует другой тип подключения, если он задан 
        в инвентаре).
    Выполняет задачи по порядку, как они описаны в плейбуке (с учётом условий, циклов, обработчиков и т. д.).
    Выводит отчёт о том, какие задачи были выполнены, какие изменили состояние системы, а какие были пропущены или 
        завершились ошибкой.

Инвентарь в Ansible — это список управляемых хостов (серверов, контейнеров, сетевых устройств и т.п.) и их 
    группировка, по которому Ansible понимает, на каких машинах запускать задачи из плейбуков

-i — это флаг в Ansible, который задаёт путь к инвентарю (файлу со списком управляемых хостов)

Когда вы запускаете, например, ansible-playbook -i inventory/test.yml site.yml, флаг -i говорит Ansible: «Не используй 
    инвентарь по умолчанию, а возьми список хостов из файла inventory/test.yml».

Без -i Ansible по умолчанию ищет инвентарь в /etc/ansible/hosts

1. **Где расположен файл с `some_fact` из второго пункта?**
   `playbook/group_vars/all/examp.yml` — переменные группы `all`, применяется ко всем хостам.
2. **Команда запуска playbook на окружении test.yml?**
   `ansible-playbook -i inventory/test.yml site.yml`
3. **Какой командой можно зашифровать файл?**
   `ansible-vault encrypt group_vars/deb/examp.yml`
   (отдельное значение — `ansible-vault encrypt_string --stdin-name 'some_fact'`)
4. **Какой командой можно расшифровать файл?**
   `ansible-vault decrypt group_vars/deb/examp.yml`
5. **Можно ли посмотреть содержимое зашифрованного файла без расшифровки?**
   Да: `ansible-vault view group_vars/deb/examp.yml`.
   Редактирование на лету: `ansible-vault edit group_vars/deb/examp.yml`.
6. **Как выглядит команда запуска playbook, если переменные зашифрованы?**
   `ansible-playbook -i inventory/prod.yml site.yml --ask-vault-pass`
   (или `--vault-password-file .vault_pass` для автоматизации)
7. **Как называется модуль подключения к host на Windows?**
   `winrm` (`ansible.builtin.winrm`); альтернатива — `psrp`.
8. **Полный текст команды для поиска информации в документации для модуля подключений ssh?**
   `ansible-doc -t connection ansible.builtin.ssh`
9. **Какой параметр модуля подключения ssh определяет пользователя?**
   `remote_user` (задаётся также как `ansible_user` / устаревшее `ansible_ssh_user`)
